# Toggle wpautop — Per-Post Review

Investigation date: 2026-08-22
Method: read-only. Queried the 11 published posts with `_lp_disable_wpautop = 1` via `wp eval` (per the working method from the earlier investigation — `wp db query`'s direct mysql path is broken on this environment). For each post, pulled raw `post_content`, checked the `custom_post_template` postmeta, scanned for block-level HTML (`<div>`, `<table>`, `<blockquote>`, etc.), existing manual `<p>`/`<br>` tags, and shortcodes, then read enough surrounding markup by hand to judge whether re-enabling `wpautop` would visibly mangle the layout. No posts, options, or plugins were modified.

**Mechanism reminder:** when `_lp_disable_wpautop = 1`, this plugin removes the `wpautop` filter from `the_content`/`the_excerpt` for that post only. Every template involved (`single-whosrunningelections.php`, `single-partyleaders.php`, `single-livebl0g-seanad.php`, `single-donotdisplayimage.php`, `single-livebl0g-template-ascough.php`, and the theme's default `single.php`) renders the post through a plain `the_content()` call — none of them do their own content reformatting — so the toggle's effect is not template-dependent; it depends entirely on what's inside `post_content`.

**Side-finding, not part of the wpautop question but relevant to "which template":** post 40809's `custom_post_template` value is `single-liveblog.php`, but no such file exists in the active theme — only `single-livebl0g.php` (digit "0" instead of "o"). The Custom Post Templates plugin's `file_exists()` check silently fails and this post falls back to the theme's default `single.php`. It still calls `the_content()`, so the wpautop analysis below is unaffected, but the post is not rendering through its intended custom template — worth a separate look if that liveblog's layout looks off.

## Summary

**10 of 11 posts still need the toggle.** All of them contain hand-authored, blank-line-separated `<div>`-based layouts (candidate grids, liveblog update stacks, pull-quote widgets, or a plagiarism-comparison grid) that wpautop's automatic `<p>`/`<br>` insertion is well known to visibly break at div boundaries. The consistent, repeated use of this toggle across five separate years of "Who's Running in the TCDSU Elections?" posts (40433, 51237, 65031, 75747) and its sibling `single-partyleaders.php` post (41252) indicates this was a deliberate, recurring fix for a known formatting problem with that template family — not incidental.

**1 post (60304) has no content to protect** and would show no visible difference either way — it's safe to leave the toggle on or off for that post specifically, though the plugin as a whole is still needed for the other 10.

**Recommendation for the plugin overall: keep.** This confirms and sharpens the earlier finding — Toggle wpautop is not just "genuinely in use," the vast majority of its actual usages are load-bearing for fragile, hand-coded page layouts on high-visibility posts (investigative pieces, election coverage, live blogs). Deactivating it would very likely introduce visible formatting regressions across most of these 11 published posts.
